# 📋 프로젝트 팀 규칙 (Team Rules)

> **프로젝트명**: 1인 진행 개인 프로젝트  
> **작성일**: 2026-10-21  
> **작성자**: 장지성  

---

### 1. ⏰ 작업 및 일정 관리 규칙
* **Daily Commit**: 하루 최소 1회 이상 진행 상황을 커밋(`commit`) 및 푸시(`push`)한다.
* **작업 분량 단위 개발**: 기능 하나 단위로 나누어 작은 단위로 커밋 메세지를 작성한다.

---

### 2. 💬 Commit Message Convention (커밋 메시지 규칙)
커밋 시 메시지 앞에 아래와 같은 태그를 붙여 어떤 작업인지 명확히 구분한다.

* `feat`: 새로운 기능 추가
* `fix`: 버그 수정
* `docs`: 문서 수정 (README, 팀 규칙 등)
* `style`: 코드 포맷팅, 세미콜론 누락 등 (코드 변경 없는 경우)
* `refactor`: 코드 리팩토링 (기능 변경 없음)

---

### 3. 🌿 Branch Strategy (브랜치 전략)
* `main`: 최종 배포 및 안정적인 코드가 저장되는 메인 브랜치
* `dev` 또는 `feature/기능명`: 혼자 개발할 때도 작업 기능별로 브랜치를 분리하여 `main`에 병합(Merge)하는 연습을 진행한다.

---

### 4. 📝 코드 스타일 및 품질 관리
* 변수명 및 함수명은 카멜케이스(`camelCase`)를 사용한다.
* 주석을 활용하여 복잡한 로직에 대한 설명을 작성한다.
